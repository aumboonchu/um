# SmartCart — เพิ่มสินค้าจากภาพหน้าจอ

อัปเดต 27 ตุลาคม 2026

## วิธีใช้งาน

1. แคปหน้าสินค้าให้เห็นชื่อ ขนาด และราคา ครอปข้อมูลส่วนตัวออก
2. เปิด [SmartCart](https://aumboonchu.github.io/um/) เข้าสู่ระบบ Google และเลือก Add Purchase → ภาพหน้าสินค้า
3. เลือก JPG, PNG หรือ WebP ไม่เกิน 10 MiB แล้วกด **อ่านข้อมูลจากภาพ**
4. ตรวจและแก้ชื่อ แบรนด์ ขนาด ราคา และรหัสที่อ่านได้ ติ๊กยืนยัน แล้วกด **ยืนยันและบันทึกสินค้าเป็น SKU**
5. เมื่อเห็นข้อความสำเร็จพร้อม SKU จึงถือว่ามีสินค้าใน D1 แล้ว หากต้องการบันทึกการซื้อ ให้กรอกราคาซื้อจริง/จำนวนและกดบันทึกรายการซื้อแยกต่างหาก

หน้า Add Purchase ใช้ภาพเป็นวิธีหลักแทนการดึงลิงก์ Big C; ยังมี UPC / เพิ่มเอง ระบบรับลิงก์เดิมคงไว้เพื่อความเข้ากันได้ แต่ไม่ใช่ปุ่มนำเข้าหลักอีกต่อไป

## การทำงานและการป้องกันข้อมูลซ้ำ

- Frontend ย่อภาพด้านยาวไม่เกิน 1,600 px และแปลงเป็น JPEG ก่อนส่ง ขนาดที่ส่งไม่เกิน 3 MiB
- `POST /api/v1/products/extract-image` ตรวจสิทธิ์/ชนิดไฟล์/ขนาด/โควตา แล้วอ่านด้วย Cloudflare Workers AI รุ่น `@cf/google/gemma-4-26b-a4b-it` การอ่านภาพไม่สร้างสินค้า
- `POST /api/v1/products/import-image` รับเฉพาะข้อมูลที่ผู้ใช้ยืนยันพร้อม UUID และ hash ของภาพ จึงสร้างหรือคืน SKU
- SmartCart ไม่เก็บภาพต้นฉบับใน D1 หรือบันทึกภาพใน log ภาพส่งให้ Cloudflare ประมวลผล; ควรครอปข้อมูลส่วนตัวก่อนส่ง
- UPC ต้องเป็นบาร์โค้ดที่เห็นชัดและผ่าน checksum เท่านั้น รหัสสินค้า Big C เช่น 60560 เก็บแยกเป็นข้อมูลอ้างอิง ไม่แปลงเป็น UPC และไม่ใช้ยืนยันรหัสในลิงก์
- D1 เก็บ receipt แยกตามผู้ใช้ + UUID; ส่งข้อมูลเดิมด้วย UUID เดิมจะได้ SKU เดิม หากข้อมูลเปลี่ยนจะปฏิเสธ
- ภาพเดียวกันและข้อมูลที่ยืนยันเหมือนกันของบัญชีเดิมไม่สร้าง SKU ซ้ำ การมี UPC ที่ตรงกันใช้สินค้าเดิม ไม่เดาจากชื่อหรือรหัสร้าน
- ก่อนส่งข้อมูลยืนยัน เบราว์เซอร์เก็บเฉพาะข้อมูลที่ยืนยันและ UUID ใน localStorage แยกบัญชี (ไม่เก็บภาพ) เพื่อกลับมาตรวจสอบด้วยรหัสเดิมหลังเปลี่ยนหน้า/รีเฟรช/เข้าสู่ระบบใหม่
- หากเก็บรหัสบนอุปกรณ์ไม่ได้จะไม่ส่งคำขอใหม่ ถ้ายังไม่ทราบผลการบันทึกจะล็อกข้อมูลและให้ตรวจสอบด้วยรหัสเดิม ไม่แสดงว่า “ยังไม่ได้บันทึก” โดยไม่มีหลักฐาน
- พื้นที่เก็บข้อมูลในเบราว์เซอร์อาจถูกล้างได้ ไม่รับประกันว่าข้อมูลที่ยังไม่ยืนยันจะไม่สูญหาย D1 เป็น source of truth
- การอ่านภาพต้องออนไลน์และเข้าสู่ระบบ Google ส่วนระบบ offline/sync ของรายการซื้อเดิมไม่เปลี่ยนแปลง

## โควตาและค่าใช้จ่าย

จำกัดการอ่านภาพ 20 ครั้งต่อผู้ใช้ต่อวัน และ 100 ครั้งรวมต่อวัน (UTC) ใน D1 นับความพยายามรวมกรณีอ่านไม่สำเร็จ โควตานี้เป็นจำนวนครั้ง ไม่ใช่การรับประกันปริมาณ neurons ทั้งบัญชี เมื่อเต็มหรือ AI ไม่พร้อม ผู้ใช้กรอกข้อมูลจากภาพเองได้

ใช้โมเดลที่รองรับ Workers Free โดยไม่อัปเกรดบัญชีหรือเพิ่มบริการเสียเงิน โควตาฟรีของแพลตฟอร์มยังมีผลและอาจหมดก่อนโควตาจำนวนครั้งของแอป ดู [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) และ [Gemma model](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/)

## ผลตรวจสอบ

- TypeScript ทั้งเว็บและ API ผ่าน; สร้างเว็บและ staging Worker dry run ผ่าน
- ชุดทดสอบเว็บ 98/98 และ API 116/116 ผ่าน รวม 214 รายการ
- ทดลองอ่านภาพ Coke ที่ผู้ใช้ส่งด้วย Workers AI จริง: ชื่อภาษาไทย, Coca-Cola, 1.95 ล., ราคา 37.00 บาท, รหัสร้าน 60560, UPC ว่าง ไม่ใช้ป้ายลดเพิ่ม 45 บาทเป็นราคา
- ทดลอง HTTP จริงกับฐานข้อมูล QA ในเครื่อง: ก่อนยืนยันสินค้า 0; หลังยืนยันสินค้า 1, receipt 1, รายการซื้อ 0; ส่งซ้ำด้วย UUID เดิมได้ SKU เดิมและจำนวนไม่เพิ่ม
- ตรวจ UI คืนรายการหลังรีเฟรช → กดตรวจสอบรายการเดิม → แสดงข้อความบันทึกสำเร็จและ SKU ตรงกับ D1 QA; ตรวจหน้าจอกว้าง 390 px ไม่พบ horizontal overflow
- ทดสอบ storage เขียนไม่ได้/ข้อมูลเสีย/เปลี่ยนบัญชี/UUID หรือ payload เปลี่ยน/401/403/409/500/timeout/ยกเลิก รวมทั้ง concurrency ฝั่ง D1
- ยังไม่ได้ทดสอบเลือกภาพครบเส้นทางบน Safari และ Home Screen ของ iPhone จริง เครื่องมือแนบไฟล์ Chrome ทดสอบติดข้อจำกัดสิทธิ์ส่วนขยาย จึงไม่อ้างว่าขั้นตอนเลือกไฟล์ผ่านบนเครื่องจริงแล้ว
- ชุดทดสอบ API ใช้ runtime ท้องถิ่นเก่ากว่าวัน compatibility ที่ตั้งไว้และมีคำเตือน cleanup ไฟล์ชั่วคราวถูกล็อก แต่ assertions ผ่านทั้งหมด
