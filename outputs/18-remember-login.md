# SmartCart — จดจำการเข้าสู่ระบบบนเบราว์เซอร์เดิม

## สาเหตุและสิ่งที่แก้ไข

เดิม API ออกเซสชันอายุ 30 วันอยู่แล้ว แต่หน้าเว็บเก็บ token ใน sessionStorage จึงหายเมื่อปิดแท็บ งานนี้เปลี่ยนเฉพาะ frontend ไม่เปลี่ยน API, อายุเซสชัน, OAuth scopes หรือฐานข้อมูล

- เก็บ opaque SmartCart session token และวันหมดอายุใน localStorage แยก key ตาม API origin ไม่เก็บรหัสผ่าน Google, Google access token หรือ ID token
- เปิดแท็บใหม่/ปิดแล้วเปิดใหม่ ใช้เซสชันเดิมและตรวจ `/auth/me` กับเซิร์ฟเวอร์ ไม่ต้องเริ่ม Google Login ทุกครั้ง
- ย้ายเซสชันเดิมจากแท็บที่ยังเปิดอยู่โดยไม่บังคับล็อกอินใหม่ และไม่ต่ออายุวันหมดอายุเดิม
- กรณี localStorage ใช้ไม่ได้ ยังคงใช้เฉพาะแท็บปัจจุบันได้และแสดงคำเตือน ไม่อ้างว่าจำถาวรสำเร็จ
- เซสชันหมดอายุ หรือ API ยืนยันว่าไม่มีสิทธิ์/ถูกเพิกถอน จะล้างสถานะล็อกอิน
- เน็ตหลุด, API 500 หรือผลตอบกลับไม่ครบถ้วน ไม่ลบเซสชันเดิม และให้ตรวจสอบอีกครั้งเมื่อออนไลน์
- การกดออกจากระบบยังเพิกถอนเซสชันฝั่งเซิร์ฟเวอร์ก่อนล้าง token ในเครื่อง เหมือนเดิม ไม่ล้างข้อมูลรายการซื้อรอซิงก์หรือข้อมูลสินค้าจากภาพที่รอยืนยัน
- แท็บอื่นรับ storage event แล้วซ่อนข้อมูลบัญชีเก่าและตรวจสิทธิ์ใหม่ ป้องกันแสดงบัญชีเก่าหลังเปลี่ยนบัญชี/ออกจากระบบอีกแท็บ
- ผลตอบกลับ 401 หรือ `/auth/me` ของ token เก่าที่มาช้า ไม่ลบ token ของการล็อกอินครั้งใหม่
- หน้าเว็บแสดงวันหมดอายุ/สถานะการจดจำ และเตือนให้ออกจากระบบเมื่อใช้เครื่องร่วมกับผู้อื่น

## ข้อจำกัดและความปลอดภัย

- จดจำสูงสุดตามวันหมดอายุเดิม (30 วันนับจากสร้างเซสชัน) ไม่ได้จดจำตลอดไป และไม่ยืดอายุอัตโนมัติ
- “เครื่องเดิม” หมายถึง browser profile/storage context เดิม ไม่ใช้ fingerprint และไม่รับประกันว่า Safari กับ Home Screen หรือเบราว์เซอร์คนละตัวจะแชร์ล็อกอิน
- โหมดส่วนตัว, การล้างข้อมูลเว็บ, storage eviction หรือการบล็อกพื้นที่เก็บข้อมูล อาจทำให้ต้องล็อกอินใหม่
- หากแท็บเดิมถูกปิดและ token รุ่นเก่าหายไปแล้ว จะกู้คืนไม่ได้ ต้องล็อกอินหนึ่งครั้งเพื่อเริ่มใช้การจดจำแบบใหม่
- localStorage อ่านได้จาก JavaScript ใน origin เดียวกัน ไม่ใช่ HttpOnly และมีความเสี่ยงหากเกิด XSS หรือมีแอปที่ไม่น่าเชื่อถือบน GitHub Pages origin เดียวกัน การแยก key ตาม API ป้องกันส่งผิด API แต่ไม่ใช่การแยกสิทธิ์ระหว่าง scripts ใน origin เดียวกัน
- Server ยังคงเป็นผู้ตรวจ hash/วันหมดอายุ/การเพิกถอนใน D1 ข้อมูลในเครื่องไม่ใช่หลักฐานยืนยันบัญชีเอง หากเปิดเว็บขณะออฟไลน์จะเก็บ token ไว้แต่ไม่สร้างสถานะ authenticated จากข้อมูลในเครื่องล้วน ๆ
- การใช้ HttpOnly first-party session จะต้องจัดโครงสร้างโดเมน frontend/API ให้เหมาะสมในงานแยกต่างหาก ไม่เปลี่ยน hosting ในงานนี้

## ผลตรวจสอบ

- TypeScript และ build เว็บผ่าน
- ชุดทดสอบเว็บ 152/152 รายการผ่าน รวมเพิ่ม auth-client 27 รายการ
- ทดสอบ UI ใน Chrome ด้วยบัญชีและ API จำลองในเครื่องเท่านั้น: เข้าสู่ระบบ → ปิดแท็บ → เปิดแท็บใหม่ → ยังได้รับเซสชันเดิมโดยไม่มี Google redirect
- เปิดสองแท็บแล้วออกจากระบบหนึ่งแท็บ อีกแท็บเปลี่ยนเป็นออกจากระบบตามผ่าน storage event
- ใช้ token จำลองบน origin สำหรับ QA ไม่ใช้/แสดง credentials หรือบัญชีจริง และไม่เขียนข้อมูลลง API/D1 จริง
- ลบไฟล์ harness ก่อนเผยแพร่ ไม่รวมข้อมูลจำลองหรือ token ทดสอบในเว็บจริง
- ยังไม่ได้ทดสอบปิด/เปิด Safari และ Home Screen บน iPhone จริง ต้องยืนยันบนอุปกรณ์เพิ่มเติม

อ้างอิง: [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [storage event](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event)
