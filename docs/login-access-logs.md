# ประวัติเข้าใช้งานสำหรับ admin

เมนูสินค้า → admin → ประวัติเข้าใช้งาน ต้อง Google Login และยืนยันรหัส admin ที่เปลี่ยนจากรหัสเริ่มต้นแล้ว ไม่ใช่หน้ารายชื่อผู้ใช้สาธารณะ

## ขอบเขต

- เริ่มเข้าสู่ Google, สร้างเซสชันสำเร็จ, ล้มเหลวระหว่าง flow ที่ตรวจสอบได้, ออกจากระบบจริง
- เข้า admin สำเร็จ/ไม่สำเร็จ และเปลี่ยนรหัส admin สำเร็จ
- เวลา UTC (แสดงตามเวลาเครื่อง), ผลลัพธ์, รหัสเหตุผลแบบ whitelist, รหัสเหตุการณ์ UUID
- อ้างอิงบัญชีที่ยืนยันแล้ว ชื่อ/อีเมลอ่านจากข้อมูลบัญชีปัจจุบัน ไม่ทำสำเนาชื่อ/อีเมลทุกเหตุการณ์
- เบราว์เซอร์/ระบบปฏิบัติการ/ประเภทอุปกรณ์แบบกลุ่ม และรหัสประเทศโดยประมาณจาก Cloudflare เมื่อมีข้อมูล ทั้งหมดเป็นเพียงข้อมูลประกอบ ไม่ยืนยันตัวเครื่องหรือตำแหน่ง

ไม่เก็บรหัสผ่าน password hash, session/OAuth token หรือ hash, cookies, IP, raw User-Agent, fingerprint, พิกัด GPS, URL/query, request body/headers, OAuth code/state/verifier, รูป หรือประวัติคลิก/ท่องเว็บ ไม่เพิ่มคุกกี้/SDK ติดตาม และไม่คัดลอก platform access logs ของ Cloudflare มาแสดง

ไม่ได้บันทึกทุก API request หรือการคืนเซสชันเดิมจาก `/auth/me` เป็น login ใหม่ และไม่สร้างประวัติย้อนหลังจากเซสชันเก่า เริ่มนับจากเวลาที่ migration 0012 ถูกติดตั้ง

## การจำกัดและรักษาข้อมูล

- `GET /api/v1/admin/access-logs`: Google session + elevated admin session ที่ยังไม่หมดอายุ/เพิกถอน/เปลี่ยน credential เท่านั้น
- อ่านแบบ `no-store` เก็บในหน่วยความจำหน้า admin เท่านั้น ไม่เก็บ log ใน IndexedDB/localStorage
- กรองเหตุการณ์/ผลลัพธ์ ใช้ keyset pagination `(occurred_at,id)` ครั้งละ 1–50 รายการ (ค่าเริ่มต้น 30) cursor ผูกกับตัวกรอง SQL ใช้ parameter bindings
- แสดงเฉพาะ 90 วันล่าสุด ลบที่หมดอายุทุกวันเวลา 03:15 UTC และขณะบันทึกเหตุการณ์ใหม่ การลบจริงอาจช้ากว่า cutoff ถึงหนึ่งรอบทำงานหรือจนระบบกลับมาทำงานได้หากบริการขัดข้อง
- FK `ON DELETE SET NULL` ไม่เก็บชื่อหรืออีเมลซ้ำเมื่อบัญชีถูกลบ ข้อมูลใน backup/ผู้ให้บริการยังเป็นไปตามนโยบายระบบนั้น ไม่รับประกันว่า backup ถูกลบทันที
- Logging เป็น best-effort และรอผลแบบจัดการ error แล้ว ไม่ทำให้ผู้ใช้เข้าใช้งานไม่ได้หลังออกเซสชันให้สำเร็จไปแล้ว ถ้า log ล้มเหลวจะแจ้งเตือนภายในด้วยข้อความคงที่ ไม่มีข้อมูลดิบ
- Log ใน D1 ไม่ใช่หลักฐานแก้ไขไม่ได้ ผู้มีสิทธิ์ฐานข้อมูลยังแก้ได้ จึงไม่อ้างว่าเป็น audit trail แบบ tamper-proof หรือครบทุกเหตุการณ์โดยไม่มีช่องว่าง

คำขอเริ่มเข้าสู่ระบบผิดรูปแบบ, Origin ไม่ตรง, state/code ที่ไม่รู้จักหรือ replay จะไม่สร้าง log แยกรายการ เพื่อไม่ให้เติมข้อมูลปลอมจนหมดโควตาฟรี Callback failure ต้องมี transaction ที่ยังใช้งานได้และ consume เพียงครั้งเดียว ส่วน verifier ผิดบันทึกได้ครั้งเดียวต่อ handoff จริงที่ยังใช้ได้ ไม่ผูกการยืนยันตัวตนที่ล้มเหลวเข้ากับผู้ใช้ที่ยังไม่ยืนยัน

## ความเป็นส่วนตัวและฐานประมวลผล

ไม่มีคุกกี้ไม่ได้หมายความว่าไม่ต้องมีฐานกฎหมาย บันทึกที่โยงกับบัญชียังเป็นข้อมูลส่วนบุคคล งานนี้จำกัดเพื่อรักษาความปลอดภัยและตรวจสอบปัญหาการยืนยันตัวตน ไม่ใช่การตลาดหรือสร้างโปรไฟล์ข้ามเว็บ

กรอบที่ใช้พิจารณาคือ PDPA มาตรา 22 (เท่าที่จำเป็น), 23 (แจ้งรายละเอียด), 24(5) (ประโยชน์โดยชอบด้วยกฎหมายพร้อมชั่งน้ำหนักสิทธิ), และ 37 (ความปลอดภัย/การลบเมื่อหมดความจำเป็น): [พระราชบัญญัติจากหน่วยงานรัฐ](https://www.dol.go.th/media/813280155698073600/2026/01/yMq60uXFbWjH97JNrP3D1pnz.pdf)

การประเมินสำหรับขอบเขตนี้: วัตถุประสงค์คือแก้ปัญหา login และตรวจจับการเข้าถึง admin ที่ไม่เหมาะสม; ไม่เก็บเนื้อหาพฤติกรรมหรือข้อมูลระบุเครื่องเฉพาะ; จำกัดผู้ดู/อายุ/ประเภทข้อมูล; มีคำชี้แจงก่อนเข้า Google และในหน้าบัญชี พร้อมช่องทางใช้สิทธิ์ผ่านผู้ดูแล SmartCart `a41s0165@gmail.com` ผู้ควบคุมข้อมูลต้องตรวจว่าฐานประมวลผลนี้เหมาะกับการใช้งานจริง รวมถึงหน้าที่อื่น เช่น ผู้ประมวลผล การส่งข้อมูลต่างประเทศ และการตอบคำขอใช้สิทธิ์ ไม่ใช่การรับรองว่าเก็บข้อมูลใดก็ได้โดยไม่ยินยอม

90 วันเป็นนโยบายที่เลือกสำหรับระบบนี้ ไม่ใช่อายุที่ PDPA กำหนดไว้ตายตัว การเข้าสู่ระบบ Google อาจใช้คุกกี้ของ Google เอง; ระบบเดิมอาจส่งคำสั่งลบ legacy session cookie ตอน logout ซึ่งไม่ใช่การสร้างคุกกี้ติดตามใหม่

## ตรวจสอบ

Migration: `0012_access_logs.sql` เป็นการเพิ่มตารางและคอลัมน์ ไม่ลบสินค้า รายการซื้อ หรือเปลี่ยนรหัสผ่าน

ทดสอบสิทธิ์ admin/bootstrap/หมดอายุ/เพิกถอน, pagination เมื่อเวลาเท่ากัน, ตัวกรองและ cursor ผิด, อายุ 90 วันและ purge, ไม่รั่วข้อมูลลับ, การปลอม header/device, การบันทึกที่ล้มเหลวไม่ทำลาย session, และการป้องกัน log amplification จาก anonymous junk
