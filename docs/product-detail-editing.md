# แก้ไขรายละเอียดสินค้า

เปิด **สินค้า → รายละเอียดสินค้า → แก้ไขสินค้า** แก้ชื่อ แบรนด์ ขนาดบรรจุ และในรายละเอียดเพิ่มเติมมีหน่วย / หมวดหมู่ แล้วกด **บันทึกการแก้ไข**

- แก้ข้อมูลสำหรับบัญชีตัวเองเท่านั้น ไม่เปลี่ยน catalog กลางหรือข้อมูลของผู้ใช้อื่น
- SKU และ UPC / EAN เป็นตัวระบุสินค้าร่วมกัน จึงอ่านได้แต่ไม่แก้ในแบบฟอร์มนี้ ไม่สลับการอ้างอิงสินค้าเดิม
- ไม่แก้ราคา จำนวน ยอดสะสม หรือรายการซื้อ ในรายงานรอบที่ชำระแล้ว ทั้งชื่อ ณ วันที่ซื้อและยอดยังเป็น snapshot เดิม
- ชื่อใหม่ใช้กับหน้าสินค้า การค้นหา/สแกนของบัญชีนี้ และ snapshot ของรอบซื้อใหม่
- ต้องออนไลน์เพื่อบันทึก ถ้าการเชื่อมต่อขาดระหว่างส่ง จะไม่อ้างว่าสำเร็จ ให้กดตรวจสอบผลด้วย UUID เดิม ไม่สร้างคำขอใหม่
- ถ้าสินค้าเปลี่ยนจากอีกแท็บ ระบบปฏิเสธการบันทึกทับ ต้องโหลดข้อมูลล่าสุดและตรวจแบบฟอร์มใหม่
- พื้นที่เก็บข้อมูลบนเครื่องขัดข้อง: ไม่ส่งคำขอใหม่ และไม่ล้าง pending เดิมอัตโนมัติ

## โครงสร้าง

`0009_product_profiles.sql` เพิ่มตาราง `product_profiles` (หนึ่งชุดรายละเอียดต่อ account/product พร้อม revision) และ `product_profile_mutations` (receipt ต่อ account/UUID) ไม่แก้ข้อมูลเก่าหรือย้าย purchase IDs

`PATCH /api/v1/products/:id/detail` ต้องมี session, Origin ของแอป และ `accountId` ที่ตรงกับ session ก่อนบันทึก ตรวจสิทธิ์จากรายการซื้อหรือ receipt นำเข้ารูปของบัญชีนั้น ปฏิเสธฟิลด์ตัวระบุ/ราคาที่ไม่อยู่ใน schema

การอัปเดตและ receipt อยู่ใน D1 batch เดียว ใช้ expected revision ป้องกัน lost update และใช้ UUID + payload hash ป้องกันส่งซ้ำ/เปลี่ยนข้อมูลใต้ UUID เดิม การ retry หลังมี revision ใหม่คืน receipt เดิม แต่ไม่ย้อนข้อมูลปัจจุบัน

API ส่วนตัวใช้ profile ตาม user ของ request เสมอ ส่วน lookup ที่ไม่เข้าสู่ระบบยังได้เฉพาะ catalog กลาง การ join history และ snapshot รอบใหม่ผูก profile ตามเจ้าของรายการ ไม่ใช่ผู้ใช้ใดก็ได้

Client รุ่นใหม่ส่ง `X-SmartCart-Profile: 1` สำหรับ product API เพื่อรับ personal profile เฉพาะเมื่อรองรับ cache แยก account แล้ว รุ่นเก่าที่เปิดค้างอยู่จะยังได้รับ canonical fields จาก lookup/detail/import ไม่เอารายละเอียดส่วนตัวไปเขียนใน shared cache รุ่นเก่า Header นี้เป็น capability hint ไม่ใช่สิทธิ์เข้าถึงข้อมูล ทุกคำขอยังตรวจ session/เจ้าของตามเดิม

Cache สินค้าที่ใช้งานจาก journey เก็บใน metadata ของ IndexedDB แบบแยก account โดยไม่เพิ่ม DB version และไม่ล้าง outbox/metadata เดิม Canonical cache รุ่นก่อนยังอ่านเป็น fallback ได้ ส่วนข้อมูลที่ระบุว่าเป็น personal profile ห้ามเขียนเข้า shared product store

## การกู้ผลคำขอ

เครื่องเก็บ payload ที่ freeze แล้วและ UUID ก่อนส่ง เมื่อ timeout, 401, account เปลี่ยน หรือผลตอบกลับไม่ชัดเจน จะเก็บคำขอไว้และล็อกแบบฟอร์ม เพื่อนำกลับมาตรวจด้วยบัญชีเดิมได้ การ logout/เปลี่ยนบัญชีไม่ควรล้างข้อมูลเว็บหรือ pending edit ของเจ้าของเดิม

ถ้า server ยืนยันบันทึกแล้ว แต่โหลดข้อมูลหรืออัปเดต cache ไม่ได้ ระบบแยกสถานะนี้ออกจากการบันทึกไม่สำเร็จ D1 ยังเป็นข้อมูลหลัก บันทึกรายละเอียดไม่ใช่การสร้างรายการซื้อใหม่
